# Version 1.13.0 release notes

Version `1.13.0` validates every successful Trino sort-order experiment against a
standalone Draft 2020-12 JSON Schema before performance automation consumes it.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Sort-order JSON Schema | Supported | The schema covers table layouts, selective ranges, alternating runs, medians, deltas, and pruning evidence |
| Runtime producer validation | Supported | `capture-trino-sort-order` validates after sort-order and scan-volume checks |
| Explicit schema override | Supported | `--report-schema` avoids conflict with the catalog `--schema` option |
| Stable control-plane verification | Preserved | 17 commands, 35 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | The Ranger policy-sync report still uses executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- The Ranger policy-sync report does not yet have a standalone schema.
- JSON Schema verifies structure and bounds; producer checks still prove identical query
  results, declared sort-order semantics, and reduced scan volume.
- The default report-schema path assumes commands run from the repository root.
- The synthetic experiment remains evidence of file-level data skipping, not a capacity
  benchmark.
- The stack remains a local reference environment, not a capacity-tested, highly
  available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.12.0

No data or infrastructure migration is required. Existing invocations use the default
report schema. Automation running elsewhere should pass `--report-schema` explicitly.
The serialized report is unchanged. Rolling back removes runtime validation.
