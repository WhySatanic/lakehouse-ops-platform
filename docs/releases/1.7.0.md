# Version 1.7.0 release notes

Version `1.7.0` validates every successful release-candidate bundle report against a
standalone Draft 2020-12 JSON Schema before returning it to release automation.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Release-candidate report JSON Schema | Supported | The schema freezes status, release target, source revision, entry count, and bundle digest |
| Runtime producer validation | Supported | `build-release-candidate` validates its report before returning success |
| Explicit schema override | Supported | `--schema` selects the reviewed schema used by automation |
| Schema drift rejection | Supported | An automated negative test makes the expected status incompatible |
| Stable control-plane verification | Preserved | 17 commands, 29 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Seven producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Seven existing public reports do not yet have standalone schemas.
- The default schema path assumes commands run from the repository root.
- The bundle report describes the archive but does not replace verification of its
  internal manifest and retained release evidence.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.6.0

No data or infrastructure migration is required. Existing invocations keep the default
schema; automation running elsewhere should pass `--schema` explicitly. Rolling back
removes runtime report validation but leaves the bundle and report fields unchanged.
