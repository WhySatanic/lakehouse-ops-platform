# Version 1.15.1 release notes

Version `1.15.1` validates a refreshed control-plane contract before it replaces the
original file. Invalid schema content and filesystem replacement failures leave the
reviewed contract unchanged and remove temporary artifacts.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Candidate validation before replacement | Enforced | The complete temporary contract passes the stable verifier first |
| Original contract preservation | Enforced | Validation and replacement failure tests compare the original bytes |
| Temporary-file cleanup | Enforced | Success and failure tests reject leaked refresh files |
| Stable control-plane verification | Preserved | 17 commands, 37 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- Digest refresh proves artifact identity and structural validity, not semantic backward
  compatibility. Maintainers must still review the schema and producer changes together.
- The refresh normalizes the contract JSON layout when replacement succeeds.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.15.0

No data, infrastructure, dependency, CLI, or report migration is required. The refresh
flag now preserves the original contract when the candidate is invalid. Rolling back to
`1.15.0` restores the earlier write-then-verify sequence.
