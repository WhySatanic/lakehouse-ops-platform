# Version 1.2.0 release notes

Version `1.2.0` makes S3-compatible landing versioning an executable recovery
prerequisite while preserving the stable `1.0.0` control-plane contract.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| MinIO bucket versioning bootstrap | Supported | `minio-init` enables versioning idempotently on new and existing buckets |
| Scoped S3 versioning readiness | Supported | `doctor --backend s3 --require-versioning` checks the bucket through the ingestion identity |
| Least-privilege readiness probe | Supported | The ingestion policy permits bucket location and versioning reads without unrestricted object listing |
| Stable CLI and JSON contract | Preserved | `verify-control-plane-contract` checks contract `1.0.0` |
| Core lakehouse, Ranger, observability, and recovery | Preserved | Required GitHub Actions integration jobs |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

The MinIO integration additionally bootstraps an isolated bucket, authenticates with the
scoped ingestion identity, and requires both the bucket access and versioning checks to
pass. Release promotion requires the pull-request CI and the resulting `main` workflow
to pass from the tagged source revision.

## Known limitations

- Versioning protects future object revisions; enabling it does not create historical
  versions for objects that already exist.
- This release verifies that versioning is enabled, but does not enforce object lock,
  retention periods, replication, or lifecycle rules.
- The S3 audit still reads current JSON objects rather than object version history.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.1.0

No command or option is removed. Run `docker compose --env-file .env run --rm
minio-init` once to enable versioning and update the scoped ingestion policy, then run
`uv run --env-file .env lakeops doctor --backend s3 --require-versioning`. Existing
objects remain current objects and are not duplicated. Suspending versioning is the
rollback, but it intentionally makes the required readiness check fail.
