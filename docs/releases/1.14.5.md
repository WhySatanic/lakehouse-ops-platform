# Version 1.14.5 release notes

Version `1.14.5` makes schema dialect and identity explicit control-plane invariants.
Every public output schema must declare the exact Draft 2020-12 dialect and a unique,
non-empty `$id` before the contract is accepted.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Draft 2020-12 dialect declaration | Enforced | Missing or different `$schema` values fail the compatibility gate |
| Schema identity | Enforced | Missing or empty `$id` values fail the gate |
| Identity uniqueness | Enforced | Duplicate `$id` values across public outputs fail the gate |
| Contract-to-schema version binding | Preserved | Each required `schema_version` const matches the declared output version |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- The gate verifies schema identities for uniqueness but does not dereference those URLs.
- Remote schema references are not fetched. Current schemas are self-contained and use
  local definitions only.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.4

No data, infrastructure, CLI, or report migration is required. Existing repository
schemas already declare the expected dialect and unique IDs. Custom contract extensions
must add an exact Draft 2020-12 `$schema` declaration and a unique `$id`. Rolling back
removes these identity checks but leaves version binding, path confinement, metaschema
validation, and runtime report validation unchanged.
