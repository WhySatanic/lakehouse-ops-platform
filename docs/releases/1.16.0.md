# Version 1.16.0 release notes

Version `1.16.0` adds offline verification for downloaded release-candidate evidence.
Operators can verify the public report schema, expected source revision, archive digest,
manifest membership, and every member digest without extracting files to disk.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Report and source binding | Enforced | Public report schema and expected source SHA are checked first |
| Archive and manifest integrity | Enforced | Bundle, manifest, and every member digest are recomputed |
| Safe archive handling | Enforced | Unsafe paths, duplicates, links, devices, and size-limit violations are rejected |
| Downloadable verification report | Implemented | A schema-validated report records all three evidence digests |
| Clean-checkout release validation | Enforced | Main CI verifies the generated assets through the public consumer command |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

The package smoke test also verifies the published `v1.15.1` report/archive pair against
its tagged source revision.

## Known limitations

- The verifier proves internal consistency and source binding, not authenticity. Obtain
  the expected SHA and assets through trusted channels.
- The bounded reader accepts at most 256 regular members, 64 MiB per member, and 256 MiB
  of total expanded content.
- The evidence target remains the stable `1.0.0` acceptance contract even as additive
  platform capabilities continue on the `1.x` line.

## Upgrade from 1.15.1

No data, infrastructure, dependency, CLI, or report migration is required. Existing build
automation remains compatible. Release automation should retain the new
`release-candidate-verification.json` output alongside the existing two assets.
