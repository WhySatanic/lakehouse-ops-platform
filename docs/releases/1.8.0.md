# Version 1.8.0 release notes

Version `1.8.0` validates every Iceberg table-health snapshot against a standalone Draft
2020-12 JSON Schema before the collector returns it to operators or automation.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Iceberg metadata report JSON Schema | Supported | The schema covers snapshot history, references, files, manifests, and partitions |
| Runtime producer validation | Supported | `collect-iceberg-metadata` validates the normalized report before returning success |
| Explicit schema override | Supported | `--report-schema` avoids conflict with the existing Iceberg database `--schema` option |
| Schema drift rejection | Supported | An automated negative test makes the expected status incompatible |
| Stable control-plane verification | Preserved | 17 commands, 30 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Six producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Six existing public reports do not yet have standalone schemas.
- The schema checks report structure and scalar constraints; cross-field totals and
  current-snapshot relationships remain enforced by integration acceptance checks.
- The default report-schema path assumes commands run from the repository root.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.7.0

No data or infrastructure migration is required. Existing invocations use the default
report schema. Automation running elsewhere should pass `--report-schema` explicitly.
Rolling back removes runtime validation but leaves report fields unchanged.
