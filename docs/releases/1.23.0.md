# Version 1.23.0 release notes

Version `1.23.0` extends destructive PostgreSQL metadata recovery to the authenticated
Ranger topology. Verified HTTPS/password queries now reconcile the cache-disabled Iceberg
catalog before backup and after restore, while the drill proves complete catalog loss,
restores the same PostgreSQL container, and preserves the catalog manifest, row count, and
snapshot ID.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Verified HTTPS transport | Implemented | Client trusts the generated Trino certificate |
| Password-authenticated reconciliation | Implemented | `platform_admin` query IDs recorded before and after restore |
| Ranger authorization boundary | Implemented | Exact security mode retained beside Ranger evidence |
| Verified PostgreSQL backup | Implemented | Custom dump SHA-256, size, TOC count, and five core tables recorded |
| Destructive catalog-loss injection | Implemented | All five core metastore tables must be absent before restore |
| Same-container restoration | Implemented | PostgreSQL container identity stays stable across every phase |
| Catalog and Iceberg reconciliation | Implemented | Manifest digest, rows, and snapshot ID match after restore |
| Failure-safe recovery | Implemented | Accepted backups restore in `finally`; Hive Metastore restarts |
| Default HTTP recovery | Preserved | Existing command and report semantics remain compatible |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run pytest
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
docker compose --profile catalog --profile compute --profile query --profile security \
  --profile secure-query --profile observability --profile serving config --quiet
```

The required Ranger integration job must validate and retain
`trino-authenticated-metadata-db-recovery.json` beside the authenticated authorization,
metastore recovery, worker lifecycle, and Ranger audit evidence.

## Known limitations

- The drill drops and recreates the PostgreSQL `public` schema in an isolated Compose
  database; it must never target a shared or production metastore.
- It proves logical single-database restore, not point-in-time recovery, WAL archiving,
  encrypted or off-site custody, PostgreSQL major-version migration, or failover.
- The retained JSON records the backup digest and contents, but the binary dump is not
  uploaded as release evidence because it contains catalog metadata.
- Worker-to-coordinator traffic uses a shared secret, not mutual TLS.
- The certificate and password file are development-only fixtures.
- Production recovery also requires independent protection for Iceberg data in S3.

## Upgrade from 1.22.0

No warehouse, metastore, CLI, or public JSON migration is required. The recovery runner
adds optional authenticated connection arguments and keeps default mode unchanged.

Rollback omits the authenticated metadata-recovery step or returns to the default command.
The drill restores its own accepted backup and does not mutate Iceberg objects or Ranger
policy.
