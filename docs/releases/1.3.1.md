# Version 1.3.1 release notes

Version `1.3.1` makes critical CLI option semantics executable within the stable
`1.0.0` control-plane contract. It changes no command behavior.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Public command and option presence | Supported | `verify-control-plane-contract` checks all 17 commands and their frozen long options |
| Critical option semantics | Supported | The verifier checks required flags, parsed types, defaults, and choices for 26 options |
| S3 recovery options | Stable | `--require-versioning` and `--include-versions` are included in contract `1.0.0` |
| Cross-platform path defaults | Supported | Path defaults use a normalized portable representation |
| Stable JSON output majors | Preserved | Ten declared reports remain on schema major `1` |
| Core lakehouse, Ranger, observability, and recovery | Preserved | Required GitHub Actions integration jobs |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

The compatibility test suite mutates each semantic dimension and requires the verifier
to reject the resulting contract. Release promotion requires the pull-request CI and
the resulting `main` workflow to pass from the tagged source revision.

## Known limitations

- The semantic baseline covers critical options rather than every option value.
- Environment-backed defaults are intentionally not frozen because deployments supply
  them independently.
- The JSON contract still uses producer tests as its field-and-type specification; it
  does not yet validate emitted reports against standalone JSON Schema documents.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.3.0

No command, option, JSON field, data, or infrastructure migration is required. Update
automation to retain the verifier report containing `option_semantics_verified`. Rolling
back to `1.3.0` removes the stronger gate but does not change runtime behavior.
