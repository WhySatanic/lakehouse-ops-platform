# Version 1.14.0 release notes

Version `1.14.0` validates every completed Ranger policy synchronization against a
standalone Draft 2020-12 JSON Schema before authorization automation consumes it.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Ranger synchronization JSON Schema | Supported | The schema covers service state, user reconciliation, managed-policy counts, and optional break-glass evidence |
| Runtime producer validation | Supported | `sync-ranger-policy` validates after Ranger reconciliation completes |
| Explicit schema override | Supported | `--report-schema` selects the reviewed automation contract |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |
| Public output schema coverage | Complete | All 11 declared public outputs have standalone schemas and runtime validation |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile query --profile security config --quiet
```

## Known limitations

- JSON Schema verifies structure and bounds; reconciliation logic remains responsible for
  cross-field counts and effective Ranger policy state.
- The default report-schema path assumes commands run from the repository root.
- Ranger remains an opt-in local profile and does not claim production identity-provider,
  TLS, or high-availability integration.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.13.0

No data or infrastructure migration is required. Existing invocations use the default
report schema. Automation running elsewhere should pass `--report-schema` explicitly.
The serialized report is unchanged. Rolling back removes runtime validation.
