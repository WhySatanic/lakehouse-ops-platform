# Version 1.14.1 release notes

Version `1.14.1` makes schema coverage a fail-closed control-plane invariant. Every
declared public output must provide a non-empty `schema_path`, and the referenced file
must exist when the compatibility gate runs.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Mandatory public-output schema declaration | Supported | The compatibility gate rejects any output without `schema_path` |
| Schema-file resolution | Supported | The gate rejects declared schema files that do not exist relative to the contract |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |
| Public output schema coverage | Enforced | All 11 declared outputs must retain a resolvable schema file |
| Runtime producer validation | Preserved | Each current producer validates its report against its standalone schema |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- The compatibility gate proves that a declared schema file exists, while each producer's
  runtime validation remains responsible for proving that emitted reports conform to it.
- Schema paths are resolved relative to the contract file and assume a complete release
  checkout or bundle.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.0

No data, infrastructure, CLI, or report migration is required. Existing repository
contracts already declare all 11 schema files. Custom contract extensions must add a
non-empty `schema_path` and distribute the referenced file with the contract. Rolling
back removes the fail-closed declaration and file-existence checks.
