# Version 1.22.0 release notes

Version `1.22.0` extends the Hive Metastore outage drill to the authenticated Ranger
topology. A verified HTTPS/password client now proves that cache-disabled catalog access
fails while Hive Metastore is stopped, PostgreSQL metadata stays online, and the same
Iceberg rows and snapshot return after catalog recovery.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Verified HTTPS transport | Implemented | Client trusts the generated Trino certificate |
| Password-authenticated catalog access | Implemented | `platform_admin` query IDs recorded before and after recovery |
| Ranger authorization boundary | Implemented | Exact security mode retained beside Ranger evidence |
| Cache-disabled outage detection | Implemented | Query must fail while Hive Metastore is stopped |
| Metadata database continuity | Implemented | PostgreSQL container stays running with unchanged identity |
| Iceberg recovery invariant | Implemented | Row count and snapshot ID match before and after recovery |
| Failure-safe restoration | Implemented | Hive Metastore restart remains in the orchestrator `finally` path |
| Default HTTP recovery | Preserved | Existing command and schema semantics remain compatible |

The required Ranger integration job must validate and retain
`trino-authenticated-metastore-recovery.json` beside the authenticated authorization,
worker lifecycle, and Ranger audit evidence.

## Known limitations

- The drill stops the Hive Metastore process but does not corrupt or restore PostgreSQL.
- It proves read-path recovery for an existing Iceberg table, not concurrent catalog
  writes or multi-metastore failover.
- Worker-to-coordinator traffic uses a shared secret, not mutual TLS.
- The certificate and password file are development-only fixtures.
- Recovery-time objectives depend on the local five-second polling and container startup
  environment; no production RTO is claimed.

## Upgrade from 1.21.0

No warehouse, metastore, CLI, or public JSON migration is required. The recovery runner
adds optional authenticated connection arguments and keeps default mode unchanged.

Rollback uses the existing HTTP recovery command or omits the authenticated Ranger step.
The drill does not mutate Iceberg tables, PostgreSQL metadata, or Ranger policy.
