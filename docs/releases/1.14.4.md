# Version 1.14.4 release notes

Version `1.14.4` binds every public output version to its JSON Schema. The control-plane
gate now requires `schema_version` in each schema and verifies that its `const` exactly
matches the version declared by the contract.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Contract-to-schema version binding | Enforced | A mismatched schema `const` fails the compatibility gate |
| Required report version field | Enforced | Schemas that make `schema_version` optional fail the gate |
| Confined schema resolution | Preserved | All schema paths remain portable and inside the contract bundle |
| Draft 2020-12 metaschema validation | Preserved | All 11 schema definitions are checked before version binding |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev

uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- The gate binds the declared version string; producer tests remain responsible for all
  other field-level and cross-field report invariants.
- The gate does not fetch remote references. Current schemas are self-contained and use
  local definitions only.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.3

No data, infrastructure, CLI, or report migration is required. Existing repository
schemas already require a matching `schema_version`. Custom contract extensions must add
the field to `required` and set its `const` to the declared output version. Rolling back
removes this binding check but leaves path confinement, schema definition validation, and
runtime report validation unchanged.
