# Version 1.14.7 release notes

Version `1.14.7` makes self-contained public output schemas fail closed on dangling local
references. The control-plane gate now resolves each local `$ref` and `$dynamicRef`
against its Draft 2020-12 schema resource and rejects missing JSON Pointers or anchors.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Local JSON Pointer resolution | Enforced | Missing `#/$defs/...` targets fail the compatibility gate |
| Local anchor resolution | Enforced | Plain-name fragments resolve through Draft 2020-12 anchors |
| Local `$dynamicRef` resolution | Enforced | Dynamic references must identify a bundled target |
| External reference rejection | Preserved | Non-fragment references remain forbidden recursively |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- Shared remote schema registries remain intentionally unsupported for public outputs.
- Resolution verifies that each local target exists; producer tests remain responsible
  for runtime report conformance and business invariants.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.6

No data, infrastructure, CLI, or report migration is required. The `referencing` package
is now a direct runtime dependency and was already installed transitively with
`jsonschema`. Custom contract extensions must correct any dangling local JSON Pointer or
anchor before adopting this version. Rolling back permits dangling local references again
but retains the external-reference restriction.
