# Version 1.6.0 release notes

Version `1.6.0` validates every successful cross-profile release-readiness attestation
against a standalone Draft 2020-12 JSON Schema before writing or printing the report.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Release-readiness attestation JSON Schema | Supported | The schema freezes evidence coverage, digests, source revision, and cross-recovery invariants |
| Runtime producer validation | Supported | `verify-release-readiness` validates its emitted attestation before returning success |
| Explicit schema override | Supported | `--schema` selects the reviewed schema used by automation |
| Schema drift rejection | Supported | An automated negative test makes the expected status incompatible |
| Stable control-plane verification | Preserved | 17 commands, 28 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Eight producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Eight existing public reports do not yet have standalone schemas.
- The default schema path assumes commands run from the repository root.
- The attestation remains specifically bound to the `1.0.0` readiness contract and its
  eight required evidence reports.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.5.0

No data or infrastructure migration is required. Existing invocations keep the default
schema; automation running elsewhere should pass `--schema` explicitly. Rolling back
removes runtime schema validation but leaves the attestation fields unchanged.
