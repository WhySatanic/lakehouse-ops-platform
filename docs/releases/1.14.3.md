# Version 1.14.3 release notes

Version `1.14.3` confines every public output schema to the control-plane contract
directory. Absolute references and paths that escape after canonical resolution now fail
before any schema is loaded.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Relative schema references | Enforced | Absolute `schema_path` values fail the compatibility gate |
| Contract-directory confinement | Enforced | Canonical resolution prevents parent traversal from leaving the contract bundle |
| Draft 2020-12 metaschema validation | Preserved | All 11 confined schema definitions are checked before acceptance |
| Runtime report validation | Preserved | Current producers validate emitted reports against the same schema files |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- Confinement is evaluated on the local filesystem after canonical resolution; release
  bundles must preserve the contract and schema directory layout.
- The gate does not fetch remote references. Current schemas are self-contained and use
  local definitions only.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.2

No data, infrastructure, CLI, or report migration is required. Existing repository
schemas already use confined relative paths. Custom contract extensions using absolute
paths or parent traversal must move their schema files inside the contract directory and
update `schema_path`. Rolling back removes path confinement but leaves schema definition
and runtime report validation unchanged.
