# Version 1.25.0 release notes

Version `1.25.0` makes the retained Ranger authorization evidence independently
verifiable before release publication. A bounded manifest now binds all 15 Ranger JSON
reports to their exact source revision, byte sizes, individual SHA-256 values, and one
canonical evidence-set digest.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Complete Ranger evidence inventory | Implemented | Exactly 15 named reports are required |
| Per-file integrity | Implemented | Size and SHA-256 are recomputed from downloaded bytes |
| Evidence-set integrity | Implemented | Canonical ordered entries produce one stable SHA-256 |
| Source binding | Implemented | Full Git SHA must match the workflow and readiness attestation |
| Bounded offline verification | Implemented | Fixed paths, file count, JSON object shape, and 16 MiB per-file limit |
| Release trust chain | Implemented | Readiness validates the manifest before the signed candidate is built |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run pytest
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
docker compose --profile catalog --profile compute --profile query --profile security \
  --profile secure-query --profile observability --profile serving config --quiet
```

The required Ranger integration job must build and immediately verify
`authorization-evidence-manifest.json`. The release-readiness job then downloads the
artifact and independently recomputes every declared digest against the exact source SHA.

## Known limitations

- The manifest is not itself a digital signature. Trust comes from the signed
  release-candidate or the digest-checked artifact download from the same CI run.
- It covers retained Ranger JSON reports, not container logs, Ranger database volumes, or
  the PostgreSQL backup binary that CI intentionally does not upload.
- GitHub artifact retention remains repository-policy dependent.

## Upgrade from 1.24.0

No warehouse, metastore, policy, CLI, or public command migration is required. Release
readiness now requires the additional manifest inside `ranger-evidence`; external evidence
producers must generate and verify it before invoking the readiness gate.

Rollback removes the transitive manifest validation from release readiness and returns to
the 1.24.0 artifact set. Existing authorization and recovery reports are unchanged.
