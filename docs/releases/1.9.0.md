# Version 1.9.0 release notes

Version `1.9.0` validates every explainable Iceberg maintenance plan against a standalone
Draft 2020-12 JSON Schema before execution automation can consume it.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Iceberg maintenance plan JSON Schema | Supported | The schema covers source snapshot, policy, checks, actions, and safety bounds |
| Runtime producer validation | Supported | `plan-iceberg-maintenance` validates the normalized plan before returning success |
| Explicit schema override | Supported | `--schema` selects the reviewed plan schema used by automation |
| JSON-native producer object | Supported | `as_dict()` returns arrays rather than Python tuples for checks and actions |
| Stable control-plane verification | Preserved | 17 commands, 31 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Five producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Five existing public reports do not yet have standalone schemas.
- Rule-specific observed values, thresholds, parameters, and extended safety bounds are
  intentionally open objects so compatible planners can add evidence fields.
- The default schema path assumes commands run from the repository root.
- The stack remains a local reference environment, not a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.8.0

No data or infrastructure migration is required. Existing invocations use the default
plan schema. Automation running elsewhere should pass `--schema` explicitly. The
normalized Python `as_dict()` result now uses lists for `checks` and `actions`; serialized
CLI JSON is unchanged. Rolling back removes runtime validation.
