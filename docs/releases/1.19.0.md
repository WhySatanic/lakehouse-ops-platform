# Version 1.19.0 release notes

Version `1.19.0` extends the opt-in authenticated Trino path from a single coordinator
to a distributed cluster with two private workers. Password authentication remains at
the HTTPS coordinator boundary, while accepted identities and Ranger policy decisions
are carried into worker-backed Iceberg queries.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| HTTPS and password authentication | Preserved | Anonymous and incorrect-password denial checks |
| Distributed secure query execution | Implemented | Three-node assertion with coordinator scheduling disabled |
| Private workers | Implemented | No host ports; unique node IDs and shared-secret internal communication |
| Centralized Ranger authorization | Preserved | Authenticated allow, deny, row-filter, and column-mask matrix |
| Default HTTP query profile | Preserved | Existing two-worker integration remains unchanged |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security \
  --profile secure-query --profile observability --profile serving config --quiet
```

The required Ranger integration job must start the secure coordinator and both secure
workers, retain `trino-authenticated-authorization-report.json`, and prove a node count
of three before release.

## Known limitations

- The secure profile is a local two-worker reference topology, not an HA deployment.
- Worker-to-coordinator traffic uses the shared-secret boundary but does not enable
  mutual TLS in this profile.
- The self-signed certificate and password file remain development-only fixtures.
- Worker loss and graceful drain drills currently exercise the default HTTP profile.

## Upgrade from 1.18.0

No data, metastore, CLI, or public JSON migration is required. Starting `secure-query`
now creates two additional worker containers and two disposable data volumes. Allow
approximately 2 GiB more container memory than the previous single-node secure profile.

Rollback stops the secure profile and removes the two secure worker volumes. The
default query cluster, Iceberg data, Hive Metastore state, and Ranger policy are not
changed.
