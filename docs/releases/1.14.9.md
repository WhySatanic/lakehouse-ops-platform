# Version 1.14.9 release notes

Version `1.14.9` rejects duplicate nested resource identifiers in public output schemas.
The control-plane gate resolves every Draft 2020-12 `$id` against its parent resource and
requires the resulting canonical URI to be unique within the schema document.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Nested resource ID uniqueness | Enforced | Duplicate canonical `$id` values fail the gate |
| Relative resource scopes | Supported | Equal relative child IDs under distinct parents remain independent |
| Anchor uniqueness | Preserved | Static and dynamic anchor names remain unique per resource |
| Local reference resolution | Preserved | JSON Pointers and anchors must identify bundled targets |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Known limitations

- Resource ID uniqueness is scoped to one standalone public schema document because
  references across documents remain intentionally unsupported.
- URI normalization follows RFC-compatible resolution provided by Python's URL utilities.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.8

No data, infrastructure, CLI, dependency, or report migration is required. Existing
repository schemas use unique resource identifiers. Custom contract extensions must rename
duplicate nested `$id` declarations and update affected references before adopting this
version. Rolling back permits duplicate resource registration again while preserving
anchor uniqueness and local-reference checks.
