# Version 1.11.0 release notes

Version `1.11.0` validates every reconciled Trino compaction comparison against a
standalone Draft 2020-12 JSON Schema before performance automation consumes it.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Compaction comparison JSON Schema | Supported | The schema covers snapshots, layouts, workload, medians, deltas, and latency direction |
| Runtime producer validation | Supported | `compare-trino-compaction` validates the report after semantic reconciliation |
| Explicit schema override | Supported | `--schema` selects the reviewed comparison schema used by automation |
| Stable control-plane verification | Preserved | 17 commands, 33 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Three producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Three existing public reports do not yet have standalone schemas.
- JSON Schema verifies structure and bounds; producer reconciliation remains responsible
  for relationships across phase and maintenance-execution reports.
- The default schema path assumes commands run from the repository root.
- Measurements remain local observations and do not define latency thresholds.
- The stack remains a local reference environment, not a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.10.0

No data or infrastructure migration is required. Existing invocations use the default
comparison schema. Automation running elsewhere should pass `--schema` explicitly. The
serialized report is unchanged. Rolling back removes runtime validation.
