# Version 1.24.0 release notes

Version `1.24.0` moves the break-glass lifecycle onto the authenticated Ranger topology.
The incident responder now authenticates over certificate-verified HTTPS throughout the
grant, expiry, and revocation drill, while Ranger remains the temporary authorization
boundary.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Verified HTTPS transport | Implemented | Client trusts the generated Trino certificate |
| Password authentication | Implemented | `incident-responder` authenticates before authorization |
| Active temporary grant | Implemented | Protected Iceberg query succeeds and records its Trino query ID |
| Expiry and revocation | Implemented | The same authenticated identity is denied after reconciliation |
| Ranger audit correlation | Implemented | Allow and deny decisions are matched by user, service, enforcer, and time window |
| Default access probe | Preserved | Existing HTTP mode remains available for local diagnostics |

## Verification

```bash
uv sync --frozen --dev

uv run lakeops verify-image-lock

  --profile secure-query --profile observability --profile serving config --quiet
```

The required Ranger integration job must retain the lease synchronization, authenticated
allow and deny probes, combined drill report, correlated audit report, and source Ranger
audit response in the `ranger-evidence` artifact.

## Known limitations

- Passwords and certificates are development-only fixtures, not a production identity or
  secret-management system.
- Expiry still requires an external reconciler; Ranger does not schedule lease removal.
- The drill proves one responder and one role binding, not concurrent incident workflows,
  approval-system integration, or a highly available scheduler.
- Audit evidence is retained by CI, not exported to an immutable production archive.

## Upgrade from 1.23.0

No warehouse, metastore, CLI, or public JSON migration is required. The development
password database adds `incident-responder`, and CI keeps authenticated Trino running until
the break-glass evidence and Ranger audit correlation are complete.

Rollback removes that development identity and runs the access probe in default mode. The
lease schema and policy synchronization contract are unchanged.
