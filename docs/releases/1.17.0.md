# Version 1.17.0 release notes

Version `1.17.0` adds cryptographic provenance for release-candidate assets. Main CI uses
GitHub OIDC and Sigstore to sign the evidence archive and both public reports, then verifies
every subject before the evidence can be retained or published.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Keyless release provenance | Enforced | GitHub OIDC certificate and Sigstore transparency evidence |
| Repository and workflow identity | Enforced | Exact repository and `.github/workflows/ci.yml` signer constraints |
| Source binding | Enforced | Exact merge SHA and `refs/heads/main` certificate constraints |
| Runner and issuer policy | Enforced | Public GitHub OIDC issuer and no self-hosted runner |
| Independent consumer verification | Implemented | Retained Sigstore bundle and machine-readable verification result |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

After merge, the `release-candidate` job must attest all three subjects and successfully
run `gh attestation verify` for each one with the identity constraints documented in the
release-candidate runbook.

## Known limitations

- Artifact attestations are a GitHub public-preview capability and their CLI surface can
  change. The action is pinned to an immutable reviewed commit.
- Provenance establishes which GitHub workflow signed an artifact. It does not protect
  against a malicious, compromised, or insufficiently reviewed workflow revision.
- Fully offline verification also needs trusted Sigstore root material obtained through
  a channel independent of the release assets.

## Upgrade from 1.16.0

No data, infrastructure, dependency, CLI, or public JSON migration is required. Release
automation must retain two additional files:
`release-candidate-provenance.sigstore.json` and
`release-candidate-provenance-verification.json`.

Rollback removes the attestation step, its job-scoped write permissions, and the two new
evidence files. Existing digest and offline bundle verification remain operational.
