# Version 1.28.1 release notes

This patch repairs confirmed commerce recovery and execution-budget defects in
`1.28.0`. It does not introduce another workload, engine, orchestration command or
release scheme. Publication requires the exact final source to pass the existing
mandatory CI and clean-checkout, same-workflow signed RC procedure. These notes
and a version change alone do not announce a published release.

## Fixes and acceptance

| Behavior | Correction and evidence boundary |
|---|---|
| Late full snapshot arrives during newer publication | A hash-bound active-batch intent is separate from completed checkpoints. After A completes and C publishes SCD2, actual MinIO arrival of B between A and C cannot displace C's retry. C completes all stages, B rebuilds retained history, the following ordinary batch completes, then idle. Real Spark/Iceberg/Trino acceptance verifies literal history and 2200 current captured cents before checkpoint. |
| Mixed timestamp precision | Ordering and late-batch comparisons use parsed UTC datetimes, including timestamps with and without fractional seconds. Existing checkpoint strings and manifest hashes remain unchanged; regression tests cover chronological selection, rebuild decisions and legacy checkpoints. |
| Budget expires during discovery or checkpoint | The shared remaining budget reaches S3 listing, manifest/body and checkpoint reads. A final guard after temporary-file fsync precedes checkpoint replacement. Expiry records no completed load; unit and real MinIO tests verify refusal and safe fresh retry. |
| Scheduled child starts after time has already elapsed | The cycle passes its original monotonic deadline to its local runner child, including launch/import/CLI time. Rechecks cannot extend a shorter runner limit. Regression tests cover startup, rounding and the final checkpoint boundary; real scheduled-cycle acceptance additionally covers Spark timeout, owned-container removal, complete retry, SQL, actual Alertmanager notification and compute-free idle. |
| Downloaded RC omits in-flight recovery | Both commerce report/checkpoint/journal triplets and the in-flight literal fixture oracle are preserved in the existing digest-bound archive. CI explicitly reruns both retained semantic checks before packaging. A missing or incomplete proof fails closed. |

Atomic customer SCD2 remains one Iceberg commit with exactly one current version
per customer. Partial customer-only maintenance still does not checkpoint a load.
Weather, Ranger, observability, maintenance and compatible commands remain
supported; ClickHouse remains an optional experiment.

## Reproduce

Prepare the reviewed local images using the README prerequisites. Choose distinct
new empty output directories and run the existing demonstrations:

```powershell
uv run --frozen python -m lakehouse_ops.commerce_history_correction_demo --output artifacts/commerce-patch-history
uv run --frozen python -m lakehouse_ops.commerce_linked_demo --inflight-late-arrival --output artifacts/commerce-patch-inflight
```

The normal-history path retains five completed batches after late correction,
caught failure, complete retry and the following ordinary batch. The in-flight
path retains four completed batches and five attempts: A, failed C after B
arrival, complete C retry, B rebuild, following ordinary batch. Both end at idle
with 2200 current captured cents and exactly one current customer version. Do not
sum revenue across complete source snapshots or count a failed attempt as a
checkpoint. Inspect the retained reports, checkpoint, SQL oracles and journal.

The [existing RC procedure](../runbooks/release-candidate.md) packages and verifies
both paths from one successful final-source workflow. Verify all three signed
subject files with the expected source revision, repository, signer workflow,
source ref, issuer and runner constraints. The release tag must resolve to that
same source. Local runs, deterministic repackaging of older inputs and an older
main's signed RC do not authorize a newer tag. The stable `1.0.0` public contract
and RC evidence target are not the product version.

## Upgrade and rollback

Keep existing named volumes, warehouse, configuration, manifests, checkpoint and
run journals. No public CLI/JSON major migration is required. Previously saved
checkpoint timestamps remain readable without rewriting them.

The active intent is a separate sibling `<checkpoint>.active.json`, not evidence
that ingestion finished. Preserve it after a failed attempt and rerun with a fresh
budget so the owner batch completes before newer queue decisions. Do not delete
the intent, reset checkpoint, edit a landed manifest or manually mark a partial
customer-only operation complete to unblock the queue. Never persist the private
cycle deadline in `.env` or reuse it for another process, host or cycle.

Before downgrading to `v1.28.0`, quiesce the writer and resolve any active attempt
with the patched runner. The older planner does not understand this recovery
intent and can reproduce the late-arrival trap; rollback is not an automatic
repair. Preserve pending inputs and data, and do not continue a fractional-time
or late-arrival workload using the affected older planner.

## Limits and measured cost

Full customer-history rebuild still requires complete retained silver history;
that documented restriction is not a fourth new review defect. One local writer
and its state own this bounded workload. Distributed coordination, automatic
orphan-stage recovery, arbitrary CDC/deletes and failure inside an Iceberg commit
remain outside the acceptance guarantee.

Reuse the [1.28.0 load/history and recovery measurements](1.28.0.md) with their
original scopes. This patch adds correctness and recovery evidence, not new
comparable performance repetitions, a throughput claim or an SLA. Demo shutdown
removes only its own containers and empty network while retaining named volumes;
it never performs global Docker pruning.
