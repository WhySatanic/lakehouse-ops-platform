# Version 1.18.0 release notes

Version `1.18.0` adds an opt-in authenticated Trino path. HTTPS and password
authentication establish the user identity before the existing Ranger plugin applies
allow and deny rules, row filters, column masks, and audit delivery.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| HTTPS coordinator transport | Implemented | Runtime-generated certificate and trusted-client query path |
| Password authentication | Enforced in `secure-query` | Anonymous HTTP 401 and incorrect-password denial checks |
| Centralized authorization after authentication | Implemented | Complete authenticated Ranger role matrix |
| Row filtering and column masking | Preserved | Authenticated analytics and administrator visibility assertions |
| Default local HTTP path | Preserved | Existing query and integration jobs remain unchanged |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query --profile security \
  --profile secure-query --profile observability --profile serving config --quiet
```

The required Ranger integration job must additionally retain
`trino-authenticated-authorization-report.json` after a live secure-coordinator run.

## Known limitations

- The certificate is self-signed, short-lived, and generated for local acceptance only.
- The checked-in password hashes all represent one documented development password.
- The secure profile is a single coordinator, not a highly available deployment.
- Password-file authentication is not an identity-provider or SSO integration.
- The original HTTP profile is intentionally preserved for existing local workflows and
  must remain bound to a trusted development machine.

## Upgrade from 1.17.0

No data, metastore, CLI, or public JSON migration is required. Start the new
`secure-query` profile only when authenticated local testing is required. Set unique
values for the three Trino authentication environment variables on any non-ephemeral
developer host.

Rollback stops the `secure-query` profile and removes its two named volumes. The default
Trino services and all lakehouse data remain intact.
