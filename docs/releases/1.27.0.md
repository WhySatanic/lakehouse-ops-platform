# Version 1.27.0 release notes

Version `1.27.0` closes the ingestion-freshness incident lifecycle. After proving that the
stale-data alert reaches Alertmanager, CI repairs the freshness timestamp through Spark,
checks the Iceberg commit, observes the resolved notification, and retains a healthy final
SLO report for release readiness.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Stale ingestion detection | Implemented | Prometheus records the breached freshness objective |
| Alert delivery | Implemented | Alertmanager sends the exact firing event to the webhook |
| Spark recovery | Implemented | A bounded update refreshes only `ingested_at` |
| Data preservation | Implemented | Row count and non-freshness content SHA-256 remain unchanged |
| Iceberg reconciliation | Implemented | Recovery must advance the table snapshot |
| Alert resolution | Implemented | Alertmanager sends the exact resolved event |
| Release health gate | Implemented | Fixture-breach SLO reports are rejected as final evidence |

## Verification

```bash
uv sync --frozen --dev
uv lock --check
uv run ruff check .
uv run pytest
docker compose --profile catalog --profile compute --profile observability config --quiet
```

The lakehouse integration job runs the full firing, repair, healthy-state, and resolved
sequence before collecting recovery and core snapshot evidence. The Spark report records
the before and after snapshot IDs, row counts, latest ingestion timestamps, and a canonical
business-content digest.

## Known limitations

- The exercise repairs the deterministic two-row silver fixture, not a streaming backlog.
- Refreshing `ingested_at` rewrites Iceberg data files and creates a new snapshot; it is not
  appropriate when the timestamp represents an immutable source fact.
- The local webhook remains an executable acceptance boundary, not a production pager.

## Upgrade from 1.26.0

No catalog, policy, CLI, or public JSON migration is required. The Compose file adds the
one-shot `spark-freshness-recovery` service under the existing compute profile. Release
readiness now requires the final SLO report to declare healthy ingestion freshness, so
custom evidence pipelines must run their recovery or refresh step before attestation.
Rollback removes the one-shot recovery drill and restores the previous fixture-breach SLO
evidence behavior.
