# Version 1.1.0 release notes

Version `1.1.0` adds a working S3-compatible landing integrity audit while preserving
the stable `1.0.0` control-plane contract.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Filesystem landing audit | Supported | Unit and CLI tests validate payload, path, and checksum failures |
| MinIO/S3 landing audit | Supported | Paginated listing, object reads, path validation, and metadata checksum tests |
| Stable CLI and JSON contract | Preserved | `verify-control-plane-contract` checks contract `1.0.0` |
| Core lakehouse, Ranger, observability, and recovery | Preserved | Required GitHub Actions integration jobs |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

Release promotion requires the pull-request CI and the resulting `main` workflow to
pass from the tagged source revision.

## Known limitations

- The S3 audit reads current JSON objects below one prefix. It does not inspect object
  version history or validate bucket retention rules.
- The checksum detects corruption and inconsistent metadata, but it is not a signature.
- A large landing zone requires one object read per JSON key and should be scheduled
  outside latency-sensitive ingestion windows.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.0.0

No command or option is removed. Existing filesystem audit invocations continue to work.
To audit MinIO or S3, add `--backend s3`, `--s3-bucket`, and the relevant endpoint and
prefix options. The audit identity needs `s3:ListBucket` for the prefix and `s3:GetObject`
for its objects. No state migration is required.
