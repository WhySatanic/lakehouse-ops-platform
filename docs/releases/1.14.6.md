# Version 1.14.6 release notes

Version `1.14.6` makes every public output schema self-contained. The control-plane gate
walks complete schema definitions and rejects external `$ref` or `$dynamicRef` values,
removing runtime dependency on remote schema registries and network availability.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| External `$ref` rejection | Enforced | Non-fragment references fail the compatibility gate |
| External `$dynamicRef` rejection | Enforced | Dynamic references cannot resolve outside the schema document |
| Local definitions | Supported | Existing `#/$defs/...` references remain valid and executable |
| Schema identity and version binding | Preserved | Dialect, unique ID, required version, and matching const checks remain active |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev

```

## Known limitations

- Shared remote schema registries are intentionally unsupported for public outputs; common
  definitions must be duplicated or generated into each standalone schema.
- The gate validates reference locality but producer tests remain responsible for runtime
  report conformance and business invariants.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.5

No data, infrastructure, CLI, or report migration is required. Existing repository
schemas use local fragments only. Custom contract extensions must replace remote `$ref`
or `$dynamicRef` values with definitions bundled in the same schema document. Rolling
back permits external references again but leaves all other schema and runtime validation
checks unchanged.
