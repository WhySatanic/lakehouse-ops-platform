# Version 1.5.0 release notes

Version `1.5.0` validates every successful image-lock report against a standalone Draft
2020-12 JSON Schema before the supply-chain gate returns success.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Image-lock report JSON Schema | Supported | The schema freezes fields, types, status, source counters, digest format, and additional-property policy |
| Runtime producer validation | Supported | `verify-image-lock` validates its emitted report before printing it |
| Explicit schema override | Supported | `--schema` selects the reviewed schema used by automation |
| Schema drift rejection | Supported | An automated negative test makes the expected status incompatible |
| Stable control-plane verification | Preserved | 17 commands, 27 critical option semantics, and 11 outputs are checked |
| Remaining report schemas | Planned | Nine producer reports still use executable producer tests |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

## Known limitations

- Nine existing public reports do not yet have standalone schemas.
- The default schema path assumes commands run from the repository root, matching the
  existing defaults for the image lock and Compose file.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.4.0

No data or infrastructure migration is required. Existing invocations keep the default
schema; automation running elsewhere should pass `--schema` explicitly. Rolling back
removes runtime validation but leaves the report fields unchanged.
