# Version 1.14.10 release notes

Version `1.14.10` binds every public output schema to a reviewed SHA-256 digest in the
stable control-plane contract. The compatibility gate now rejects missing, malformed, or
mismatched `schema_sha256` values during schema validation.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Public schema digest binding | Enforced | All 11 outputs declare a lowercase SHA-256 digest |
| Schema drift rejection | Enforced | Changed schema bytes fail until the contract digest is reviewed |
| Cross-platform stability | Enforced | CRLF and LF line endings produce the same normalized digest |
| Schema structure checks | Preserved | Dialect, IDs, anchors, references, and versions remain validated |
| Stable control-plane verification | Preserved | 17 commands, 36 critical option semantics, and 11 outputs are checked |

## Verification

```bash
uv sync --frozen --dev

uv run lakeops verify-image-lock

docker compose --profile catalog --profile compute --profile query --profile security --profile observability --profile serving config --quiet
```

## Known limitations

- A schema edit requires an explicit digest refresh in the contract, including compatible
  additive edits and formatting changes other than line endings.
- Digest approval proves artifact identity, not semantic backward compatibility by itself;
  the structural gate and producer tests remain mandatory.
- The stack remains a local reference environment, not a capacity-tested or multi-region
  managed service.

## Upgrade from 1.14.9

No data, infrastructure, CLI, dependency, or report migration is required. Custom
control-plane contracts must add the normalized SHA-256 of each referenced schema as
`schema_sha256`. Rolling back removes digest enforcement while retaining schema identity,
resource, anchor, and reference checks.
