# Version 1.20.0 release notes

Version `1.20.0` extends abrupt Trino worker-loss recovery to the opt-in authenticated
Ranger profile. The drill now crosses the HTTPS/password boundary, kills the private
worker selected from live task evidence, proves a safe retry on the surviving worker,
and restores the secure three-node topology without changing Iceberg state.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| Verified HTTPS transport | Implemented | Recovery client trusts the generated Trino certificate |
| Password-authenticated recovery queries | Implemented | `platform_admin` and `lakehouse-operator` identities recorded in the report |
| Abrupt private-worker loss | Implemented | Live task-to-node mapping followed by `SIGKILL` |
| Degraded-cluster retry | Implemented | Protected Iceberg fingerprint succeeds with one worker |
| Secure topology restoration | Implemented | New container ID and three active nodes after recreation |
| Ranger decision delivery | Preserved | Recovery report retained beside the validated Ranger audit artifact |
| Default HTTP recovery drill | Preserved | Existing report semantics and `query` profile remain compatible |

The required Ranger integration job must retain
`trino-authenticated-worker-recovery.json`, validate its authenticated security boundary,
and retain the Ranger Solr audit report after the drill.

## Known limitations

- Recovery means a safe client retry after scheduler convergence. In-flight execution is
  expected to fail because the profile uses `retry-policy=NONE`.
- Worker-to-coordinator traffic uses a shared secret, not mutual TLS.
- The certificate and password file are development-only fixtures.
- Ranger audit retention proves decision delivery for the authenticated test run but does
  not correlate each audit document to a recovery-report query ID.
- Coordinator failover and concurrent writes during worker loss are not covered.

## Upgrade from 1.19.0

No warehouse, metastore, CLI, or public JSON migration is required. The recovery runner
adds optional authenticated connection parameters and preserves the existing default
mode. Existing secure-profile users only need to provide the generated CA certificate
and password when invoking the authenticated drill.

Rollback uses the previous default recovery command or stops the `secure-query` profile.
The Iceberg tables, Hive Metastore state, Ranger policy, and default Trino cluster are not
changed by the capability.
