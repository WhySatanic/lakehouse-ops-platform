# Version 1.3.0 release notes

Version `1.3.0` adds an executable audit of retained S3-compatible landing object
versions while preserving the stable `1.0.0` control-plane contract.

## Capability matrix

| Capability | Status | Evidence |
|---|---|---|
| S3 landing version-history audit | Supported | `audit-landing --backend s3 --include-versions` validates every retained JSON version |
| Delete-marker inventory | Supported | The audit reports marker identifiers and whether each marker is latest |
| Scoped history access | Supported | The ingestion identity receives prefix-bound version listing and object-version reads |
| Real MinIO history path | Supported | CI writes two versions and audits both with scoped credentials |
| Stable CLI and JSON contract | Preserved | `verify-control-plane-contract` checks contract `1.0.0` |
| Core lakehouse, Ranger, observability, and recovery | Preserved | Required GitHub Actions integration jobs |

## Verification

```bash
uv sync --frozen --dev
uv run ruff check .
uv run lakeops verify-control-plane-contract --contract config/control-plane/contract.json
uv run lakeops verify-image-lock
uv run pytest
docker compose --profile catalog --profile compute --profile query config --quiet
```

The lakehouse integration bootstraps versioned MinIO storage, writes the same
deterministic landing key twice, and requires both versions to pass payload, path, and
metadata checksum validation through the scoped ingestion identity. Release promotion
requires the pull-request CI and the resulting `main` workflow to pass from the tagged
source revision.

## Known limitations

- The command audits and inventories history but does not restore an object version.
- Delete markers are recovery evidence and do not make a history audit fail; run the
  regular current-object audit to verify what readers can see now.
- Versioning does not provide retention guarantees without object lock or lifecycle
  controls, which remain outside this release.
- The audit reads every JSON version under the selected prefix, so operators should use
  a narrow prefix for large landing zones.
- The stack remains a local reference environment rather than a capacity-tested,
  highly available, TLS-enabled, or multi-region managed service.

## Upgrade from 1.2.0

No command or option is removed. Run `docker compose --env-file .env run --rm
minio-init` to add `s3:ListBucketVersions` and `s3:GetObjectVersion` within the existing
landing boundary. Then run `uv run --env-file .env lakeops audit-landing --backend s3
--include-versions`. No object migration is required. Restore the previous ingestion
policy to roll back; current-object audit and ingestion continue to work, but history
inspection becomes unavailable.
